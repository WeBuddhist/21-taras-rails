## Structural decisions recorded in the source chat

Stated by the generating session, kept here because they are invisible from the files alone:

1. **The pre-publication review lives canonically in `16-wikipedia`**, with
   `14-source-publication` and `15-wikidata-sync` referencing it as their gate rather than
   duplicating it — one copy means step-13 patches cannot cause the gate to drift across
   three files.
2. **Steps without canonical prompts** (14, 15, 17, and the routing half of 3) carry
   procedure/invariant sections derived strictly from the pipeline document, with an explicit
   note that they have no canonical prompt — so the step-13 feedback loop knows patches for
   those steps are behavioral, not prompt edits.
3. **Step 3's TF-IDF script is declared missing** in the vault the skills were written for;
   that skill takes the term list as a supplied input. *In this repo the gap does not exist*:
   `4-SYSTEM/Skills/english-keyword-extraction/` (YAKE/TF-IDF) and `tibetan.keyness` are the
   TF-IDF half, proven on tara21 (`scripts/enrich_tara21_terms.py`).

## Which model runs which step

The canonical design is **two models with different jobs** — "the stylist is never trusted;
the auditor never writes":

| Steps | Canonical model | Why |
|---|---|---|
| 6–10 (passages, outliers, claims, outline, draft) | Claude | reading, structuring, judgment |
| 11 (polish) | **Gemini** | writes better literary Tibetan — the one step that *requires* Gemini, and the only one with a Gemini script (`scripts/gemini_polish.py`) |
| 12 (audit) | Claude | a model is a poor judge of its own drift; the auditor must not be the writer |

This repo is headless and ships only a Gemini client, so `kwiki article` runs every model
stage on Gemini by default. That is a **deliberate, documented divergence, not a silent one**:
the run prints a note whenever the audit ran on the model that drafted, `--audit-model` gets
at least cross-model independence, and `scripts/claude_article.py prompt|apply <term> <stage>`
is the Claude route (the repo's headless equivalent of a Cowork skill) for `claims`, `draft`
and `audit`. Use it for anything whose audit numbers will appear in the paper.
