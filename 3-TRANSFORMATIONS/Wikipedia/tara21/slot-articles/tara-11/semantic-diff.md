- **Issue:** Gemini's returned prose apparently had its trailing blank line trimmed. Because the script concatenates the polished body directly onto the frozen tail with no separator, the last sentence of `== བསྡུས་དོན། ==` ("...འགྲེལ་པའི་ལུགས་སྣ་ཚོགས་ཡོད་པ་ཤིན་ཏུ་གསལ་ལོ།།") was glued directly onto the following heading with zero characters between them: `...ཤིན་ཏུ་གསལ་ལོ།།== འབྲེལ་ཡོད་ཤོག་ངོས། ==`. In MediaWiki, a `==...==` heading not on its own line does not render as a heading — this would have broken the "Related pages" section on publish.
- **Detection:** found by diffing the reassembled `article.md` against the pre-polish baseline (git commit capturing the file as it stood immediately before this run) restricted to heading/related-links/category lines — every other heading, the related-pages list, `== ལུང་ཁུངས། ==`, `== དཔྱད་གཞིའི་ཡིག་ཆ། ==`, and the trailing category tag were confirmed byte-identical to the pre-polish tail; only this one boundary was corrupted.
- **Fix (surgical reversion, Rule 8a):** re-inserted the blank line between the summary paragraph and the heading in `article.md`, restoring `...ཤིན་ཏུ་གསལ་ལོ།།\n\n== འབྲེལ་ཡོད་ཤོག་ངོས། ==`. No wording was changed — only the separator that the reassembly step had dropped was restored. `body-after.txt` was left untouched as the raw model record. `article-preview.md` was regenerated after the fix. A full scan of every heading and the category line in the corrected file confirms each is now preceded by a blank line, and no other paragraph-boundary concatenation defect exists elsewhere in the document.
- **Not covered by C1–C7:** none of the script's hard checks verify that a fixed-tail heading is preceded by a line break, so this class of defect can pass hard checks silently. Worth flagging to the skill maintainer as a gap in the checker (not fixed here, per instructions not to hand-patch the skill/script itself — only the article output was corrected).
