# Spine map — tsultrim-namdak

> Routing index only. This file records **which of this commentary's own TOC nodes hold
> which canonical spine slot's content** — nothing about what the claims say. It never
> quotes, interprets, or restates a claim; `assemble_packet.py` copies the claim text
> itself verbatim out of `2-RAILS/Claims/raw/tree-guided/tsultrim-namdak.md` at packet time.
> Every claim in that file has exactly one disposition below.

**Structure of this commentary.** This is not one commentary but a nine-work anthology bound
into a single volume (`0` front matter/colophons, `1`–`9` the nine works, `9` the printer's
colophon). Only two works touch the root praise directly: Work 2 (node `2`), whose child
`2.1.1` is the origin-narrative (ལོ་རྒྱུས) explicitly registered in the annex as this slot's
first observed instance, and whose grandchild `2.1.2.1` runs the verse-by-verse gloss of all
twenty-one homages undivided in one node — boundaries are the "Verse N quoted" claims: e.g.
`c-2-1-2-1-2` quotes homage 1, `c-2-1-2-1-71` quotes homage 21. Work 3 (node `3`, a flat leaf
with no sa-bcad subdivisions of its own) is an independent parallel commentary that also
covers all twenty-one homages, but one claim per verse (`c-3-4`…`c-3-24`), each glossed under
its own name for that Tārā form. Work 8 (node `8`) reproduces the bare root praise as a single
undivided recitation-text (`c-8-4`) followed by a benefits-colophon that quotes the root's own
`^a-1`–`^a-6` verbatim (`c-8-5`), before moving to an unrelated White Tārā praise (`8.1`).
Works 1, 4, 5, 6, 7 and node `9` are, respectively, a different praise, a story collection, two
ritual sādhana texts, an unrelated three-kāya prayer, and the volume's print colophon — none
of them comment on individual homages, matching the annex's own examples of legitimate
unmapped material ("front matter, colophon, ritual appendices … and story collections").
Several coarse nodes (`2`, `2.1.2`, `3`, `8`, `8.0`) mix a handful of the sub-work's own
title/opening-homage/attribution/colophon claims together with claims that route to a real
slot; since node-based routing sweeps the whole subtree (Rule 4), these orphan claims are
pulled out individually via Claim-level routing. No registered slot exists for "a sub-work's
own front matter" as such; they are parked under `structure` as the closest existing
organisational slot, flagged here for a human contributor's attention — a dedicated slot
(e.g. `frontmatter`) may be worth registering if this recurs across the corpus.
