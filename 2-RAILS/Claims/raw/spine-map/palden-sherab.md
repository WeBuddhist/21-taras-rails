# Spine map — palden-sherab

> Routing index only. This file records **which of this commentary's own TOC nodes hold
> which canonical spine slot's content** — nothing about what the claims say. It never
> quotes, interprets, or restates a claim; `assemble_packet.py` copies the claim text
> itself verbatim out of the raw claims file at packet time. Every claim in that file has
> exactly one disposition below.

**Structure of this commentary.** Pseudo-node `0` (front matter: guru/lineage homage,
transmission narrative, and the author's own announcement of a four-part division — title,
translator's-homage, text-meaning, closing-meaning) precedes the numbered tree, whose nodes
`1` and `2` gloss that title and translator's-homage respectively. Node `3` (གསུམ་པ་གཞུང་དོན,
"text-meaning") is the spine-bearing branch: its own direct claim states the two-part
division into individual praise (`3.1`) and general benefits (`3.2`). Under `3.1`, each of
the twenty-one homages gets its own node (`3.1.1`–`3.1.21`), titled by ordinal-plus-epithet
in exact correspondence with the root text's `^1-1`–`^1-21` (e.g. `3.1.1 མྱུར་མ་དཔའ་མོ` = the
first homage, "Swift Heroine"), each holding two own claims (identification + root-verse
quotation, e.g. `c-3-1-1-0-2` quoting `^1-1`) plus four numbered sub-nodes elaborating the
literal/general/hidden/ultimate meaning announced by `3.1`'s own direct claim. Under `3.2`,
node `3.2.1` (the principal cause of the benefits) and `3.2.2` (the six-part explanation of
the benefits proper, quoting a benefits-verse at `c-3-2-1-1`) both address the closing ཕན་ཡོན
section (`^a-1`–`^a-7`); node `3.1.22` closes the homage run with a summary statement, and
node `4` is the commentary's own colophon and dedication.
