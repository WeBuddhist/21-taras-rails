## Human note — all 70 flags are a checker/format artifact, not real hallucinations

`qc_check_tree.py`'s `_TREE_LINE_RE` regex only strips a trailing `^toc-N-N` block-ID
suffix; it does not know about this vault's `[[N]]` line-pointer convention (the format
`qc_tree_vs_source.py` and the promoted `karma-maitri`/`lobsang-dawa` trees actually use —
see `0-INBOX/toc-tree-qc-lobsang-dawa.md` for the identical precedent). Every one of the 70
nodes above is a **short, recurring, low-syllable-count title** (`གཉིས་པ་སྤྱི་དོན`,
`གསུམ་པ་སྦས་དོན`, `བཞི་པ་མཐར་ཐུག`, bare `དང་པོ` / `གཉིས་པ` / … for the six 3.2.2.x benefit
items, plus `3.` and `3.2`) — when the trailing `[[N]]` is left unstripped in the matched
title text, the fuzzy bigram-coverage check has too few real syllable-pairs left to clear
the threshold, so it reports 0% coverage regardless of whether the title is genuinely
attested.

Verified as a false positive by re-running the identical checker against a copy of this
same tree with only the `[[N]]` suffixes stripped (content otherwise byte-identical):

```
$ sed -E 's/ \[\[[0-9]+\]\]$//' 0-INBOX/toc-tree-palden-sherab.md > /tmp/tree_no_pointers.md
$ python3 4-SYSTEM/Skills/toc-tree-extraction/scripts/qc_check_tree.py \
    /tmp/tree_no_pointers.md \
    --corpus 0-INBOX/toc-candidates-palden-sherab.md 0-INBOX/toc-enumerations-palden-sherab.md
✓ 0 issue(s) — tree is clean.
```

Every flagged title is copied verbatim from a Pass-1 `SECTION_TITLE` candidate or matches
the bare ordinal actually written at its `[[N]]` source line (see
`0-INBOX/toc-tree-qc-source-palden-sherab.md`, which checks titles against the source
itself and reports only 1 issue — a heuristic sibling-count note, see below — plus 1 note
about bare-ordinal titles). Treated as **0 real corpus-attestation issues** for promotion
purposes.
